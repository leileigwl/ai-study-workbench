### Q1.1 为什么用懒时间戳计算代替后台定时线程？
- **标准答案要点（`3` 个）**：
  1. **零空转开销**：只对当下有请求进来的 Key 做 $O(1)$ 加减乘除，百万级冷用户完全零 CPU 消耗。
  2. **消除周期性锁竞争**：不用后台定时扫全量字典与正常业务抢锁。
  3. **平滑无锯齿突发**：连续时间差不会把流量挤在固定整秒 tick 后集中爆发。
- **漏点追问话术（绝不直接剧透）**：
  - *若漏掉第 1 点*：“假设系统有 50 万注册账号，此刻同时在线的只有 2,000 个。如果后台线程每 100ms 扫一遍全量桶加令牌，服务器 CPU 在忙什么？”

### Q1.2 直接用 `time.time()` 或不清理冷 Key 会出什么故障？
- **标准答案要点（`2` 个）**：
  1. **时钟回拨倒扣**：NTP 校时往回跳导致时间差变负数，反向扣光用户可用令牌。
  2. **内存无限泄漏**：恶意伪造一次性随机 Key 会永远占着内存直到网关 OOM 崩溃。
- **漏点追问话术**：
  - *若漏掉第 2 点*：“黑客拿 500 万个随机假 IP 发请求，你的限流器全成功拦截了 429，为什么 15 分钟后网关还是 OOM 挂了？”
